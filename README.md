# Messthon UI Demo

**Messthon UI Demo** — мультипротокольный мессенджер, который объединяет Matrix, XMPP и будущие протоколы в одном рабочем пространстве. Это готовый к запуску frontend-прототип с полноценной навигацией, адаптивными компоновками, демонстрационными данными и Material Design 3.

**Демо:** [https://kirilldual0987.github.io/mst-UI-demo/](https://kirilldual0987.github.io/mst-UI-demo/)

**Репозиторий:** [https://github.com/kirilldual0987/mst-UI-demo](https://github.com/kirilldual0987/mst-UI-demo)

> Сетевые подключения, авторизация и реальная отправка сообщений в этой версии отключены. Все данные демонстрационные. Архитектура подготовлена для подключения протокольных адаптеров.

---

## Быстрый запуск

Требуется Node.js **20.19+** (проверено на Node.js 24).

```bash
cd Messthon
npm install
npm run dev
```

Откройте адрес, который выведет Vite: **http://127.0.0.1:5173/mst-UI-demo/**.

### Production-сборка

```bash
npm run build
npm run preview
```

Предпросмотр production-сборки: **http://127.0.0.1:4173/mst-UI-demo/**.

### Проверки

```bash
npm run typecheck   # TypeScript, без emit
npm run lint        # ESLint 9 + TypeScript
npm run test        # Vitest: фильтры и поиск
npm run build       # tsc -b + production build
```

## Возможности

### Основной экран

- Единая лента всех аккаунтов и протоколов.
- Закреплённые чаты, непрочитанные сообщения, избранное.
- Отдельные представления: все сообщения, личные, группы, комнаты и сообщества.
- Компактная метаданные каждой переписки: протокол, аккаунт, статус, вложения.
- Поиск по локальному списку переписок.
- Контекстное меню чата и действия: прочитано, закрепить, избранное, уведомления.

### Мультипротокольность

- Быстрый фильтр Matrix / XMPP прямо в рабочей области.
- Фильтр по конкретному аккаунту через отдельный popover.
- Аккаунты не смешиваются: идентичность аккаунта отображается в шапке чата, композере и панели информации.
- Список аккаунтов с подключением, синхронизацией, ошибкой соединения и удалением.
- Добавление нового аккаунта Matrix или XMPP с имитацией подключения.
- Протокольные настройки Matrix и XMPP находятся на отдельных страницах.

### Чат

- Полноценная история сообщений с датами, группировкой и прокруткой.
- Текстовые сообщения, изображения, файлы, цитаты, ответы, реакции и системные сообщения.
- Разделитель непрочитанных и действие «Прочитано».
- Статусы отправки/доставки и квитанции о прочтении только там, где они уместны.
- Отправка текста, загрузка изображений и файлов, панель эмодзи, реакции.
- Контекстное меню сообщения и быстрые действия.
- Просмотр изображений в lightbox.
- Информационная панель с участниками, общими файлами и протокольной безопасностью.

### Контакты

- Поиск, группировка по алфавиту, фильтры «онлайн», «избранные», Matrix и XMPP.
- Профиль контакта с общими переписками, медиа и параметрами протокола.
- Добавление контакта с привязкой к выбранному аккаунту.
- Быстрый переход к переписке.

### Настройки

Отдельные маршруты для каждой категории:

- Внешний вид — тема, акцентный цвет, размер и плотность интерфейса.
- Интерфейс — видимость протокольных подписей и панели информации.
- Сообщения — Enter/Shift+Enter, квитанции, индикатор набора.
- Аккаунты — статусы и управление идентичностями.
- Протоколы — сводка Matrix и XMPP.
- Matrix — homeserver, ключи, устройства, комнаты и Spaces.
- XMPP — JID, ресурсы, присутствие, MUC и OMEMO.
- Уведомления, приватность, безопасность, шифрование.
- Хранение данных, горячие клавиши, сведения о приложении.

Настройки сохраняются в `localStorage`: тема, акцент, размер, плотность, протокольные подписи, поведение ввода и другие параметры.

### Компоновки

| Диапазон | Компоновка |
| --- | --- |
| ≥ 1280 px | Полный рабочий стол: навигация, список переписок, чат, информационная панель; перетаскиваемые разделители и изменение ширины клавиатурой. |
| 768–1279 px | Компактная навигация-рейл, список переписок и чат; информационная панель открывается поверх. |
| < 768 px | Самостоятельная мобильная компоновка: полноэкранные экраны, нижняя навигация, выдвижное меню, мобильная шапка чата и панель информации. |

Проверенная адаптивность: **375×812, 390×844, 768×1024, 1024×768, 1366×768, 1920×1080**. Горизонтальная прокрутка отсутствует.

### Доступность

- Семантические кнопки и поля с подписями.
- Видимый focus-ring, клавиатурная навигация, закрытие диалогов по Escape.
- Focus trap в модальных окнах.
- Контрастность проверена через axe-core на основных экранах.
- Учитывается `prefers-reduced-motion`; есть отдельная настройка уменьшения движения.
- Крупные зоны взаимодействия на мобильных экранах.

## Архитектура и будущая интеграция

1. **Нормализованные данные.** `src/types.ts` описывает аккаунты, контакты, чаты и сообщения без привязки визуальных компонентов к SDK Matrix или XMPP.
2. **Состояние приложения.** `src/state/AppContext.tsx` и reducer содержат операции с демонстрационными данными. Компоненты не выполняют сетевых запросов.
3. **Границы протоколов.** `src/adapters/protocolAdapter.ts` определяет контракт `ProtocolAdapter` и capabilities для Matrix и XMPP. Реальная реализация сможет транслировать SDK-события в нормализованные `ChatMessage`, `Chat` и `Contact`.
4. **Специфичный UI.** Компоненты Matrix и XMPP различают идентификаторы, шифрование, комнаты, MUC, ресурсы и квитанции. Эти возможности не выводятся как универсальные.
5. **Темы и дизайн-токены.** Все цвета, радиусы, отступы и состояния заданы в `src/styles/tokens.css`; светлая и тёмная темы используют одни токены.
6. **Маршрутизация.** React Router: `/messages`, `/direct`, `/groups`, `/rooms`, `/favorites`, `/unread`, `/contacts`, `/accounts`, `/settings/:section`.

## Ограничения прототипа

- Нет реальных сетевых подключений, авторизации, федерации и протокольных SDK.
- Добавление аккаунтов/контактов и отправка сообщений работают в локальной демонстрационной сессии (состояние сбрасывается при перезагрузке; настройки сохраняются).
- Push-уведомления, звонки, OMEMO/Megolm-ключи, создание групп и управление правами комнат обозначены через демонстрационные уведомления.
- Файлы изображений и вложений локальные; внешние ресурсы не загружаются.
- Для production-развёртывания нужен сервер с fallback на `index.html` для клиентских маршрутов.
